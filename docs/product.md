# FuelForm MVP 范围

个人使用的原生 iPhone 应用，最低 iOS 17，中文界面，系统浅深色。个人记录在本机；手动记餐与训练无需网络。无账户系统、商业化、社交、HealthKit、Watch、视频动作分析、自动减脂处方或复杂 Agent。

## 已写入实现的流程

- 今日：当天目标快照、已确认摄入、剩余额度、消耗与缺口、餐次和安排，明显的记餐入口；进入前台和定时刷新跨午夜日期。
- 饮食：按日期补录；早餐、午餐、晚餐、加餐；多个食物项目、整餐总热量、八项带来源食物库；保存草稿、确认、编辑、删除。
- 图片：系统相册选择器或相机 → 归一化并保存本机文件 → 主动点击分析 → 可编辑草稿 → 用户确认。支持后端 Mock、真实适配以及显式的本地固定演示。原始分析每次追加保留，已确认餐次再分析只能创建新草稿。
- 训练：手动编辑每天安排，训练日/休息日、基础动作库、目标组数/次数范围/重量/休息；复制首周到 1–12 周；重叠启用计划被拒绝。AI 条件包括周数、天数、时长、器械、经验、目标和避开动作。草稿需确认启用。
- 实际训练：明确开始才创建日志；每组实际次数、kg、完成状态；增删实际组、替换动作、跳过、休息倒计时、保存与历史编辑。过去日志包含独立目标副本。
- 我的：可留空的资料、手动摄入目标和总消耗、明确更新今日快照开关、体重记录与图表、服务连接检查、Keychain 凭据、JSON 分享导出。

以上是代码实现范围；App 尚未经 iOS 编译与设备验收，运行证据见 progress.md。本地演示是固定米饭示例，不理解图片；训练 Mock 用固定保守规则，不能称为个性化 AI。

## 产品决策

1. 总消耗只用手动估算。没有资料时不虚构身高/体重；不实现自动公式，避免额外假设。计划与实际动作均不自动折算热量。
2. 餐次归属固定到录入/补录时当地公历日，旅行后不会重排历史。保存 UTC 时间戳与时区 ID。
3. 未记全仅展示已记录摄入和估算余额；没有已确认餐次且未明确记全时显示未知。今天即使勾选记全仍表示截至目前。
4. 设置更新只影响以后新建快照。用户可显式更新今日或单个历史日期；补录日期初次快照采用当前设置，界面提醒核对。
5. 草稿可带照片、暂不含食物。已有项目需通过基本数值校验才保存。草稿取消不生成正式记录。
6. 记录数据量较小，采用 SwiftData 的每个聚合一条版本化 Codable 信封，避免多个食物/组关系联动修改历史。将来可迁移到更细粒度实体。
7. JSON 不是完整照片备份，不支持导入恢复。后续优先做完整备份与迁移演练。

演示数据分区：Meal.isDemo明确标记，饮食页独立显示且不计入个人汇总；Mock计划保留demo标记，禁止直接启用。用户主动核对并点击转为个人草稿后才可确认使用，原始演示来源继续保留。
